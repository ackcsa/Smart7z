Smart7z 用户手册

Smart7z 是一个面向 Windows 的批量解压工具，可处理分卷、加密压缩包、文件内嵌 ZIP 和嵌套压缩包。手册前半部分讲操作，后半部分列出状态、配置和模块说明。

最终交付分为安装版、便携版和源码版。安装版与便携版可直接运行且自带 7-Zip；源码版保留一方源码、测试、构建配置和安全的空白资源模板。

窗口名称：Smart 7z Ultra 适用平台：Windows 安装/便携版：自带 7-Zip 图形界面：Tkinter

开始前请确认

Smart7z 把批量文件、分卷、加密压缩包、文件内嵌 ZIP、嵌套压缩包和源文件清理放在同一个队列中逐项处理。完整输出通过校验后才会移到最终位置；未完整成功但仍可使用的文件会单独保留。

开始解压选择交付版本，启动程序，添加文件并运行队列。 了解解压选项查看输出位置、暂存模式、空间等待和三种扫描模式。 查看实现查阅功能、任务状态、程序模块和配置项。
默认保留源文件：安装版、便携版和源码版的首次运行配置都使用 cleanup_policy=keep，不会自动清理源压缩包。需要清理时必须明确选择“回收站”或“永久删除”；第一次使用永久删除前应在常驻的 解压选项 行核对设置。
外部任务不会沿用窗口中的清理选项：普通命令行和未指定清理参数的第二个程序实例默认使用 keep。右键菜单会分别提供“智能解压到此文件夹”和“智能解压到此文件夹并删除”：前者保留源文件，后者使用 permanent，成功后永久删除源文件。图形界面中添加的任务仍会记住入队时所选的清理策略。

快速开始

  1. 选择版本。安装版适合固定使用；便携版应先完整解压到可写目录；源码版用于审阅、测试或二次开发。安装版和便携版自带 7z.exe，源码版需要系统安装 7-Zip，或在源码根目录放置 7z.exe。
  2. 启动程序。安装版从开始菜单启动，便携版双击 Smart7z.exe，源码版在源码根目录运行 python smart7z.py。如果 Smart7z 已经打开，新进程会把路径交给现有窗口，不会再打开一套任务队列。
  3. 选择输出位置。勾选“解压到原目录”时，每个压缩包的输出放在其所在目录；取消勾选后，所有输出都放到“目标目录”。
  4. 检查设置。尤其要确认 源文件清理。菜单栏“文件扫描模式”默认选择“仅兼容隐写者模式（非全读取）”，“选项”菜单控制空间不足时是否等待；下方解压选项保留输出、暂存、嵌套和清理设置。
  5. 添加文件。少量文件可用“添加文件”或直接拖入窗口；整批处理目录时用“扫描文件夹”。目录扫描会自动排除普通文档和媒体文件，并在默认兼容模式下跳读识别 SteganographierGUI 的 MP4/MKV 隐写 ZIP。
  6. 点击“开始”。程序保存当前设置，并优先处理待处理任务中体积较小的压缩包；大小相同时保持入队顺序。某个任务等待密码或内嵌 ZIP 候选选择时，队列中的其他任务仍可继续，人工输入完成后的恢复任务会优先继续。
cd <Smart7z 源码目录>
python smart7z.py

# 发送路径并自动开始
python smart7z.py --start "D:/Downloads/example.7z"

# 发送路径但只入队，等待你在窗口里点“开始”
python smart7z.py --queue "D:/Downloads/example.7z"

首次启动检查

  • 安装版和便携版已经自带 7-Zip。源码版若弹出“找不到 7z.exe”，请安装 7-Zip 或把 7z.exe 放到源码根目录，再重启。
  • 若弹出“依赖缺失：未检测到 tkinterdnd2”，只影响拖拽；可以继续使用“添加文件”和“扫描文件夹”。
  • 若点击“开始”时配置保存失败，先把目标目录、暂存目录和密码文件改成当前用户有写权限的位置。
  • 随附的 code.txt 为空；需要自动尝试密码时，按“一行一个密码”自行填写。安装器只在该文件不存在时部署空模板，覆盖安装和升级不会覆盖已有密码本，卸载时也会保留。若旧安装地址已有非空密码本，而新的状态目录只有空占位或尚无密码本，程序会继续使用旧地址。该文件是明文，请勿加入公共仓库或对外分发。
  • 安装模式默认把配置、恢复日志、单实例状态和相对密码文件放到 %LOCALAPPDATA%/Smart7z。EXE 同目录存在 portable.flag 时改用便携模式，文件会写到 EXE 目录；该目录只读时无法保存设置。

取消扫描后重新扫描

目录扫描在后台进行，找到的文件仍由界面线程加入队列。程序会给每次扫描分配独立编号，因此取消后立即重扫时，上一批延迟返回的结果不会混进新一批。

情形系统行为用户可见结果
点击“取消所有”当前扫描编号作废，同时清空“待接纳”列表；后台线程检测到取消后退出。尚未加入队列的旧结果会被丢弃，可以立即重新选择文件夹。
旧扫描的结果延迟返回界面检查结果携带的扫描编号，编号已作废就不再接收。不会覆盖新扫描，也不会把取消前发现的文件重新加回队列。
结构检查耗时较长分块搜索签名、读取 ZIP 中央目录和遍历 BMFF box 时都会检查取消信号。通常会在处理完当前数据块或结构后停止；正在等待的系统文件调用需要等调用返回。
扫描线程出错程序记录异常，并把本次扫描标记为结束，随后继续处理下一个请求。已经加入队列的项目不受影响，界面也不会一直停在“已有扫描进行中”。
“取消当前”和“取消所有”的区别：“取消当前”只处理正在运行的任务；“取消所有”保留当前任务，但取消其他未完成任务，还会取消目录扫描并丢弃未加入队列的扫描结果。关闭窗口时，程序先停止接收新请求和单实例通信，再等待仍在运行的扫描线程退出。

运行日志

运行日志用来确认程序是否接到请求、操作结果如何，以及接下来是否需要人工处理。任务的普通进度和成功状态已经在任务表中显示，不会再逐项抄到日志里。

一行日志怎样读

[HH:MM:SS] {文件名或来源}: 中文说明 / English message [MESSAGE_CODE] | {系统详情}
  • 时间、文件名、来源、错误分类、数量和路径等共用信息只写一次，不在中英文说明里重复长路径。
  • 方括号中的代码固定不变，可用于搜索本手册。中文和英文说明由同一份消息目录生成。
  • | 后只放 Windows、Python 或恢复模块返回的原始诊断。这部分可能只有英文，程序会原样保留，避免改坏路径、异常类型或系统错误。

红色标记

红色用于从批量日志中找出非正常结果。时间戳保持原色；颜色只帮助扫读，处理问题时仍以消息文字、稳定代码和任务详情为准。

显示方式消息代码含义
整条消息显示为红色JOB_FAILED、ARCHIVE_BLOCKED、CONFIG_SYNC_FAILED、RECYCLE_FAILED、RECYCLE_FALLBACK_DELETE_FAILED任务、配置、安全预检或源文件清理已经失败，需要先查看详情再继续。
只把重点短语显示为红色粗体RECOVERY_REVIEW、INTAKE_FULL、SCAN_FAILED、JOB_PARTIAL_RECOVERY、JOB_INTERRUPTED、JOB_PASSWORD_REQUIRED、USER_NOTICE、RECYCLE_FALLBACK_UNAVAILABLE、RECYCLE_FALLBACK_TOO_LARGE操作仍可继续，或程序已经保留可恢复内容，但其中有需要确认的结果。原始系统详情保持普通颜色，避免整段诊断压过重点。
保持原色其他消息代码正常状态、操作确认和汇总信息。

哪些内容会写入

内容是否写日志在哪里查看完整状态

解压选项

设置保存与生效范围

程序不再提供单独的“保存配置”菜单项。正常关闭窗口时，程序会读取当前路径、菜单栏扫描模式与空间等待、下方解压选项、嵌套层数和清理策略，校验后以“先写临时文件、再替换原文件”的方式保存；点击“开始”时也会先执行同一套保存与应用流程，成功后才开始处理。

操作或任务状态实际行为
只修改窗口控件部分控件不会在每次点击后立即写盘，但通过当前窗口新添加文件或启动文件夹扫描时，“清理策略”和扫描模式等入队参数可能已经被记录。希望整批一致时，应先设置选项，再添加输入。

正在处理的任务任务启动时会取得一份配置快照，后续修改不会中途改变该任务。队列中尚未开始的任务会在点击“开始”保存后使用新的普通执行设置，但其入队时记录的清理策略不会被改写。
命令行、右键菜单或第二个进程转交的路径只读取已经提交的配置，不读取当前窗口里尚未通过“开始”提交的控件值。正常关闭时保存的设置会在下次启动后生效。清理策略和“解压到此文件夹”仍以该次外部请求的明确参数为准；未指定清理策略时使用“保留”。
主密码不会落盘：“主密码”输入框只更新当前程序会话中的密码候选，不会写入 smart7z_config.json。保存的是密码文件路径，不是密码文件内容。

配置文件位置取决于运行模式：安装版位于 %LOCALAPPDATA%/Smart7z，便携版位于 EXE 目录，源码版位于源码根目录的 resources。详细字段见 配置项。

输出位置：解压到原目录 / 目标目录

勾选“解压到原目录”时，每个任务输出到源压缩包所在目录。取消勾选时，所有任务输出到“目标目录”。如果目标目录为空且又取消了“解压到原目录”，应先填写一个绝对路径，避免配置保存或运行失败。

暂存模式

开启暂存模式后，7-Zip 先把内容解压到临时目录。程序随后检查路径安全、文件和目录清单、数量、已知大小、7-Zip 返回码以及输出上限。

检查全部通过后，程序把输出移到目标盘上的隐藏暂存目录。普通文件全部写入磁盘后，再以不覆盖现有文件的方式移到最终位置。

解压到临时目录→ 检查路径和输出上限→ 核对文件、目录和大小→ 写入目标盘暂存目录→ 移到最终位置

临时目录和目标目录在同一磁盘时，程序直接移动文件，并要求 Windows 等待写入完成，不会为了 CRC32 再读一遍全部输出。跨盘时，程序在复制过程中计算压缩包清单中已有的成员 CRC32，并检查写入长度；不会再读取一遍目标文件。CRC32 不一致时，输出会转入“非完全恢复”目录，源压缩包保持不变。

关闭“暂存模式”后的行为：程序仍不会直接写入最终路径，而是在目标目录下建立 .smart7z_tmp_... 临时目录，校验通过后再移动输出。两种模式的主要区别是初始解压位置：开启时使用“暂存目录”，关闭时使用目标目录所在磁盘。

空间等待

在菜单栏“选项”中勾选“空间不足时等待”后，程序根据压缩包清单、输出上限和安全余量检查可用空间。暂存模式会同时检查目标盘和暂存盘，关闭暂存模式后只检查目标盘。空间不足时，任务进入 SPACE_WAIT，默认最多等待 7200 秒（2 小时）。取消对钩只会跳过等待，解压过程中仍可能因空间不足而失败。

扫描模式

菜单栏“文件扫描模式”包含三项，并以对钩表示当前唯一选择。默认的“仅兼容隐写者模式（非全读取）”只在 BMFF 的 ftyp/free 原子、MP4 文件尾以及 Matroska 的 EBML/SeekHead/Attachments 元数据处定位 SteganographierGUI ZIP，不顺序读取视频主体。

“深度扫描模式（全文件读取）”适用于 JPEG、未知容器或需要查找任意位置候选的目录。它先用非全读取兼容探测识别 SteganographierGUI 的结构和诱饵尾缀；命中时直接复用精确 ZIP 候选，未命中才对文件做流式结构预检，同时查找 ZIP、7z 和 RAR 候选。“普通模式”关闭这两类特殊目录扫描，只保留常规压缩格式与轻量内容分类。直接添加、拖入或通过命令行指定的文件也会优先识别隐写者结构；嵌套任务始终不会进行深度结构扫描。

嵌套解压

开启后，父任务完成或产生部分恢复输出时，程序会扫描其输出目录，把发现的内层压缩包作为新任务加入队列。扫描受 max_nested_depth、max_nested_children 和 max_nested_output_bytes 限制。结构有效的普通 Windows EXE 会保护其本目录和父目录，防止游戏或程序资源包被继续解压；保护不会越过当前输出根，改名压缩包和边界完整的 ZIP/7z 自解压文件仍可继续处理。

安全预检与自动跳过

每个压缩包在解压前都使用同一套清单、路径和资源限制，没有手动放行入口。命中限制时任务显示为“失败”，运行日志写入 ARCHIVE_BLOCKED 和专属原因，源压缩包保留，不产生正式输出，队列自动继续处理下一个任务。

正常压缩包不会因名称中含空格、中文、点文件、等号、普通多级相对目录而被拦截；加密标记、普通 Unix 文件权限、常规分卷也不属于路径风险。程序只拒绝在 Windows 上无法安全落盘、会发生名称冲突，或无法完整验证的结构。

普通解压流程

  1. 使用 添加文件 或拖拽加入一个或多个普通 .7z、.zip、.rar、.tar 等文件。
  2. 确认 源文件清理策略。不确定时选“保留”。
  3. 点击“开始”。程序先保存设置，再由调度器逐个处理队列中的任务。
  4. 程序识别压缩包和分卷，读取内部清单，检查空间与路径安全，然后解压并核对文件、目录和大小。
  5. 状态变为 COMPLETE 时，输出已经写入最终位置并通过复查。状态变为 PARTIAL_RECOVERY 时，程序只保留仍可恢复的输出，不会清理源压缩包。

密码压缩包

密码只在当前处理过程中临时使用，不会写入长期保存的任务记录；7-Zip 命令写入日志前也会隐藏密码。密码候选文件是明文文件，主密码输入框也不能替代密码管理器，请勿把密码文件发到公共渠道。

候选顺序

本次手动输入→ 本批次成功密码→ 无密码探测→ 密码文件逐行候选→ 弹出密码输入

使用方法

  • 密码文件使用纯文本，一行一个密码；当前配置默认文件名是 code.txt，相对路径会按程序目录解析。
  • 同一批加密包共用一个密码时，可先填“主密码”，再开始队列。
  • 一个密码成功后，会成为本批次后续加密包的优先候选，并提升到密码文件顶部；密码值不会写入任务记录或运行日志。
  • 文件头可见的加密包会复用无密码状态下已经取得的完整清单；等待手动密码期间源文件未变化时，重新入队也不会再次读取清单。文件头加密、清单不完整或源文件已变化时仍会重新列出。
  • 已经确认加密的包在解压阶段不会再做必然失败的无密码尝试。若列清单时某个密码已经成功解锁文件头，解压会先尝试这个已验证密码。
  • 手动密码提交或跳过后，密码输入内容会立即清空，提示区自动收起，任务表和详情区恢复原来的可用高度。
  • 点击“跳过”会把该任务标为 SKIPPED，源文件不会被清理。
密码文件限制：文件超过 4 MiB 时会整份忽略；程序最多使用前 10,000 个有效候选，超过 4,096 个字符的单行候选也会忽略。

Smart7z 会把同一组分卷合并为一个任务，并从首卷开始处理，避免重复解压。分卷齐全、解压完成且检查通过后，源文件清理会按整组分卷执行。

  2. 添加任意一卷。程序会自动找到同组文件，并从首卷开始处理。

扫描文件夹

“扫描文件夹”会遍历所选目录，并自动判断哪些文件应加入队列，适合一次处理目录中的普通压缩包。

程序如何筛选文件

  • 程序先轻量读取文件头和文件尾。常见 7z、RAR、CAB、WIM、TAR、ISO、DMG、VHD 和压缩数据流已有明确结构证据时，不再扩大边缘读取范围；ZIP 仍会继续核对中央目录。
  • 菜单栏“文件扫描模式”默认勾选“仅兼容隐写者模式（非全读取）”。它只识别 SteganographierGUI 的普通 MP4 追加 ZIP、mp4(zarchiver) free 原子 ZIP 和 MKV 附件 ZIP。
  • 兼容模式跳读 BMFF 原子或 Matroska EBML/SeekHead 元数据，只定点读取 ZIP 尾部、中央目录和被引用的本地文件头；视频主体和大型 Cluster 按已知长度直接跳过。
  • 选择“深度扫描模式（全文件读取）”时，兼容模式和普通模式会取消选择，但程序仍先执行隐写者非全读取探测。命中时直接使用真实 ZIP 边界并忽略随机尾缀诱饵；未命中的文件才用同一轮流式读取查找 ZIP、7z、RAR 候选。
  • Office 文档、APK、JAR、MSI、PDF、媒体和可执行文件即使内部带有压缩结构，也会按其实际文件类型处理，避免批量误解压。
  • 复合扩展名如 .tar.gz、.tar.xz 会作为压缩包候选。
  • 直接添加或拖入的文件不经过目录语义筛选，但在 7-Zip 打开失败后同样优先识别隐写者结构和诱饵尾缀，未命中才进入通用候选扫描。
默认不会全读媒体文件：兼容模式只对 SteganographierGUI 支持的 MP4/MKV 布局做跳读定位。需要寻找 JPEG、未知布局或任意位置候选时，改用“深度扫描模式（全文件读取）”；扫描过程中可以取消。
自动开始的目录任务：程序会先完成本次目录扫描并把候选整批加入队列，再按源包大小从小到大开始解压，避免扫描到的第一个大文件抢先占用处理线程。

适用和不适用

目标建议入口原因
整理下载目录里的普通压缩包扫描文件夹效率高，自动跳过大量文档和媒体。
处理扩展名错误的普通压缩包“添加文件”或命令行文件路径直接指定文件会绕过目录扫描的自动筛选，适合人工确认过的文件。
处理 SteganographierGUI 的 MP4/MKV保持默认兼容模式后扫描文件夹只跳读容器元数据和 ZIP 结构，不顺序读取媒体主体；候选通过精确边界校验后自动入队。
处理 JPEG 或未知布局的内嵌 ZIP深度扫描，或直接添加文件深度扫描会顺序读取文件；直接添加适合已经人工确认的单个文件。
普通 CLI / IPC 批量处理外部入口默认使用 keep；只有显式指定 --delete-source 才使用永久删除。
资源管理器右键处理两个右键菜单项根据所选菜单保留或永久删除源文件；两项都会把输出放在源文件所在目录。

伪装文件与内嵌 ZIP

Smart7z 可以快速定位 SteganographierGUI 创建或兼容的 MP4/MKV 隐写 ZIP，并识别其 ZIP64 记录、两组诱饵签名、随机区和空 mdat 尾缀。兼容结构只返回真实 ZIP；深度扫描、直接添加和拖入未命中兼容结构时，才继续查找其他完整 ZIP。找到多个通用候选时，任务会进入“隐写候选”状态供选择。

它能识别什么

普通 MP4 追加 ZIP

兼容 ZIP 直接结束于文件尾，以及隐写者当前版本的两组诱饵签名、随机区和空 mdat 尾缀。

ZArchiver free 原子

验证 ftyp 后的 free 原子，并要求完整 ZIP 与原子载荷边界精确一致。

MKV ZIP 附件

通过 EBML 和 SeekHead 定位 Attachments/FileData；跳过大型 Cluster，再校验附件内完整 ZIP。

操作步骤

  1. 处理隐写者 MP4/MKV 时，保持菜单栏“仅兼容隐写者模式（非全读取）”开启，然后扫描文件夹。
  2. 未知布局未被发现时，可改用“深度扫描模式（全文件读取）”，或使用“添加文件”直接选择单个文件。
  3. 点击“开始”。如果直接 7-Zip 打开失败且发现候选，会显示候选列表。
  4. 选择来源可信、边界完整的高置信候选。解压和校验通过后，程序会像普通任务一样保存输出。
  5. 如果存在多个候选、候选边界仍不确定，或任务只能部分恢复，程序不会清理原文件。

所有自动入队候选都必须通过 ZIP/ZIP64 中央目录、本地文件头、条目数量和精确边界检查。发现多个候选时，需要人工选择。

嵌套解压

嵌套解压默认关闭。开启后，父任务把文件写入最终位置，程序再扫描这些输出，把内层压缩包作为子任务加入队列。子任务沿用父任务的清理策略和嵌套限制，并执行与外层任务相同的安全预检。为避免把游戏和程序资源误当成压缩包，扫描会先识别结构有效、但没有可确认自解压载荷的 Windows EXE，并保护该 EXE 所在目录及其父目录；保护边界不会越过本次压缩包的输出根目录。

源文件清理

程序只有在任务状态为 COMPLETE、最终输出复查通过、源文件没有变化、分卷信息可靠，并且内嵌 ZIP 候选没有歧义时，才会清理源文件。普通命令行和第二个程序实例默认使用 keep；指定 --delete-source，或选择右键菜单“智能解压到此文件夹并删除”时，任务使用 permanent。任务加入队列后会固定本次清理策略，之后修改窗口选项不会改变它。

策略行为何时使用风险
keep / 保留保留源压缩包。首次使用、需要核对结果、重要资料或来源不明的文件。继续占用磁盘空间。
recycle / 回收站先检查每个源文件所在卷的回收站设置。可以回收时只允许移入回收站；卷明确不支持回收或文件超过该卷容量上限时，改走有恢复日志保护的永久删除。希望通常可以恢复，同时接受两类明确条件下永久删除。锁定、权限、配置读取或 Shell 调用失败时会停止。分卷任务已经处理的卷不会自动撤回。
permanent / 永久删除成功后再次检查源文件的设备号、文件标识、大小和修改时间，先在恢复日志中记录操作，再把文件移入同盘隐藏暂存目录并永久删除。空间不足，且文件已有备份或可以重新获取。删除后无法从回收站恢复；中途失败时，程序会保留或恢复尚未删除的文件。

“回收站”策略怎样决定删除方式

清理一组分卷前，程序先确认所有源文件仍在原处。它根据卷 GUID 读取当前用户的 NukeOnDelete 和 MaxCapacity，并核对每个文件的大小。只要有源文件缺失，或有一项设置读不清，整组清理就在其他源文件发生变化前停止。

检查结果程序怎么做能否恢复
固定磁盘允许使用回收站，文件没有超过该卷的容量上限通过 Windows IFileOperation 执行严格回收，并使用 FOFX_RECYCLEONDELETE 禁止 Shell 暗中改成永久删除。可以从回收站恢复。
非固定磁盘，或该卷启用了 NukeOnDelete，或 MaxCapacity 为 0先写恢复日志，再把源文件移入同盘隐藏暂存目录并永久删除。不能从回收站恢复。
单个源文件大于该卷的 MaxCapacity使用同一套恢复日志和暂存流程永久删除，不让 Windows 自行决定是否暗删。不能从回收站恢复。
源文件在预检后发生变化，卷设置未知，或遇到文件锁定、权限错误、COM / Shell 错误停止清理，不把这类错误解释为永久删除许可。尚未处理的源文件保留。

执行时先处理能够严格回收的文件，并在每次调用 Shell 前重新核对该源文件的身份；随后再集中暂存需要永久删除的文件。暂存阶段失败时，程序会把已经暂存的文件恢复原位；永久删除开始后如果某一卷失败，后续卷不再删除，并从暂存区恢复。

分卷任务何时可能只处理一部分：整组预检失败时，一个卷都不会动。只有预检全部通过、清理已经开始后，后面的卷又遇到运行时错误，才会出现部分处理。此前移入回收站的卷仍可手工恢复；此前因“回收站不可用”或“文件过大”而永久删除的卷不能恢复；尚未处理的卷会留在原处或从暂存区恢复。任务详情和运行日志会记录停止原因。

清理会被阻止的情况

  • 状态不是 COMPLETE，例如 FAILED、PARTIAL_RECOVERY、INTERRUPTED、SKIPPED。
  • 7-Zip 读取清单或解压时返回警告，并且没有唯一、边界精确的高置信候选可以确认结果。
  • 分卷缺失、分卷元数据与发现结果不一致，或卷索引不可信。
  • 源文件缺失、是链接或重解析点，或者任务运行期间其设备号、文件标识、大小、修改时间发生变化。
  • 跨盘移动输出时，复制得到的成员 CRC32 与清单不一致，或文件、目录、数量、大小不一致。
  • 输出写入磁盘、移动到最终位置、更新恢复日志或暂存源文件时失败。
  • 内嵌 ZIP 候选存在歧义，或候选边界仍不确定、置信度较低。

恢复与临时文件

Smart7z 用恢复日志记录自己创建的会话目录、解压输出暂存目录和源文件暂存目录。写恢复日志和所有权标记时，程序先写入同目录临时文件并调用 fsync，再要求 Windows 等内容写入完成后替换正式文件。记录无法可靠写入时，程序会中止相应的输出移动或源文件清理。

对象典型名称用途处理建议
会话临时目录Smart7z_Session_...暂存模式下保存解压输出和中间文件。正常退出或下次启动时，会清理所有权可验证且只剩所有权标记或空 stego 脚手架的会话；存在未登记内容、链接或重解析点时保留。

源文件暂存目录.smart7z_cleanup_...永久删除前，在源文件所在磁盘暂时保存已复查的文件。中断后优先恢复到原路径；原路径已有文件时，转移到可见的冲突目录。
部分恢复目录非完全恢复保存出现警告、CRC32 不一致，或输出移动和复查未完全成功时仍可恢复的文件。人工检查后再移动或删除。

断电或进程意外退出后：尚未移到最终位置的已登记输出会保留下来，下次启动不会把它当成普通临时目录删除。如果永久删除停在“源文件已经移入暂存目录，但尚未删除”，下次启动会根据设备号、文件标识、大小和修改时间复查并恢复原路径；原路径已有文件时，则移到可见的冲突目录，不会覆盖现有文件。

命令行、单实例与右键菜单

命令行

# 默认：路径会自动开始
python smart7z.py "D:/Downloads/a.7z"

# 只加入队列，不启动处理
python smart7z.py --queue "D:/Downloads/a.7z"

# 明确自动开始
python smart7z.py --start "D:/Downloads/a.7z"

# 解压到源文件所在目录，并保留源文件
python smart7z.py --start --extract-here --keep-source "D:/Downloads/a.7z"

# 解压到源文件所在目录；完整成功后永久删除源文件
python smart7z.py --start --extract-here --delete-source "D:/Downloads/a.7z"

# 停止解析选项，后面的值都当路径
python smart7z.py -- --queue

--queue 和 --start 控制任务何时开始；--keep-source 和 --delete-source 控制源文件清理。没有指定清理参数时使用 keep。--extract-here 会忽略窗口中配置的目标目录，把每个任务的输出放在其源文件所在目录。

单实例 IPC

程序启动后会监听一个仅供本机使用的进程间通信（IPC）端口。再次启动 Smart7z 时，新进程读取状态文件并校验令牌，然后把路径、启动方式、清理策略和输出位置要求发送到已有窗口。请求有消息大小和路径数量限制，只接受已经存在的本地绝对路径。

Windows 启动阶段还使用命名互斥量保证只有一个进程能够创建窗口、调度器和恢复日志。资源管理器多选文件后执行右键菜单时，Windows 可能为每个选中项分别启动一个短生命周期辅助进程；未取得启动权的进程会等待主实例建立 IPC，再把各自收到的路径转交给同一个窗口，不会同时打开恢复日志。若已有实例正在关闭，新进程会在有界时间内继续重试转交并等待互斥量释放；旧实例退出后由取得互斥量的新进程接管，不会在恢复日志仍被占用时启动第二个调度器。

转发结果与新进程的处理

结果含义新进程如何处理
accepted已有实例已登记请求，或者窗口已成功切到前台。新进程正常退出；目录请求随后按扫描和“待接纳”规则处理。
rejected请求到达已有实例，但队列已满、程序正在关闭，或请求未能加入队列。队列拒绝等确定失败会以非零状态退出；仅当原因为 server_stopping 时，Windows 新进程会继续有界重试并等待接管，避免关闭竞态丢失右键请求。
indeterminate请求已到达，但新进程没有收到可靠确认，无法判断是否已加入队列。不打开第二个窗口。先检查现有窗口的队列，再决定是否重试。
unavailable找不到可信的现有实例状态，或无法连接。先争取启动互斥量；已有进程正在启动时最多等待 15 秒并重试转交，前一进程退出时则接管。等待超时不会创建第二个调度器。

从外部一次发送多个路径时，程序先检查整批路径能否放入等待队列。容量不足会整批拒绝，不会只留下前一部分。目录扫描正在运行时，后续文件和目录按收到的顺序进入“待接纳”列表。每批任务会保留请求中指定的清理策略和输出位置要求；没有显式指定时使用 keep，并按当前输出配置处理。

右键菜单

顶部“右键菜单 → 添加右键菜单”会为当前 Windows 用户的文件和目录添加两个资源管理器菜单项：

菜单项输出位置源文件处理

两个菜单项都会自动开始处理。右键选择目录时，程序先扫描该目录，再把找到的压缩包逐项加入队列；清理策略和输出位置要求会传给扫描得到的任务及其嵌套任务。框选多个压缩文件执行同一个菜单项时，资源管理器可能逐个启动辅助进程，但这些请求会在启动互斥阶段串行化并分别转交到唯一窗口，所选文件不会因为恢复日志锁冲突而启动失败。

程序在解压前仍会读取完整成员清单，以便在写文件前检查条目数、输出大小、路径穿越、Windows 名称冲突、链接、备用数据流和分卷信息。清单现在直接按 7-Zip 输出流解析，不再保留整份大文本；正常包的主要收益是降低峰值内存，条目数超过 max_manifest_entries 或 max_output_files 时会在第“上限 + 1”条停止 7-Zip，从而避免继续扫描超限清单。

右键窗口何时自动关闭

只有“最初由资源管理器右键菜单创建”的独立窗口具备自动关闭资格。程序会等待本批右键请求停止到达，并确认所有已接纳任务均为 COMPLETE、目录扫描和“待接纳”列表均已结束、调度器没有当前任务或延后任务、也没有密码或内嵌 ZIP 候选提示，随后按正常关闭流程保存当前配置并退出。

  • Smart7z 已经由开始菜单、双击、普通命令行或图形界面打开时，右键任务只会加入这个现有窗口；该窗口不会因右键任务完成而自动关闭。
  • 窗口虽然最初由右键菜单创建，但处理期间又双击 Smart7z 打开程序时，现有窗口会被激活到前台，并立即取消本次自动关闭。之后任务正常完成也会保留窗口。
  • 框选多个压缩包时，每个后续右键请求都会重新开始短暂的接收等待；旧的关闭检查会作废，避免第一个小压缩包先完成时漏掉后续文件。
  • 只要出现失败、部分恢复、中断、跳过、需密码、内嵌 ZIP 候选复核、目录扫描失败、请求未接纳、任务通知、启动恢复需复核，或 IPC 分发、界面回调、自动关闭阶段发生未预期程序异常，窗口就会保留，便于查看状态、日志和专属错误。没有发现或接纳任何任务时也不会自动关闭。
“并删除”不会使用回收站：源压缩包通过全部清理检查后会被永久删除。需要保留恢复余地时，请选择不带“并删除”的菜单项。
注册与升级：右键菜单写入 HKCU/Software/Classes 下的当前用户注册表项，一般不需要管理员权限。升级到包含双菜单的版本后，请先关闭旧实例，再运行新版并重新执行“右键菜单 → 添加右键菜单”；程序会移除旧的单菜单项。非 Windows 系统或当前用户无权写入该位置时，注册会失败。

常见任务

整理下载目录中的压缩包

  1. 在常驻的“解压选项”行选择“保留”或“回收站”。首次不要选永久删除。
  2. 勾选下方“暂存模式”，并在菜单栏“选项”中勾选“空间不足时等待”。
  3. 点击“扫描文件夹”，选择下载目录。
  4. 检查任务表是否只包含预期压缩包。
  5. 点击“开始”，处理完成后清除已完成任务。

处理一组使用相同密码的 7z

  1. 把常用密码写入密码文件，一行一个。
  2. 如果本批次密码统一，直接填“主密码”。
  3. 添加所有 .7z 文件。
  4. 点击“开始”。出现密码提示时输入正确密码，成功后会提升到密码文件顶部。

解压隐写者 MP4/MKV 中的内嵌 ZIP

  1. 打开菜单栏“文件扫描模式”，确认“仅兼容隐写者模式（非全读取）”已经勾选。
  2. 使用“扫描文件夹”；普通 MP4 追加 ZIP、ZArchiver free 原子和 MKV ZIP 附件会跳读定位后加入队列。
  3. 如果未知布局没有找到，开启“深度扫描模式（全文件读取）”，或点击“添加文件”直接选择媒体文件。
  4. 开始处理。若候选列表出现多个候选，只选择来源可信且边界完整的高置信候选。

只加入队列，暂不运行

  1. 使用 GUI 添加文件或拖入文件，默认只入队。
  2. 或者使用命令 python smart7z.py --queue "D:/a.7z"。
  3. 确认队列、选项和清理策略后，再点击“开始”。

windows_adapters.pyWindows 集成。读取卷级回收站设置，执行严格回收，提供永久删除、右键菜单、长路径、本地盘判断和会话清理。
