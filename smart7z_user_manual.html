Smart7z 用户手册

Smart7z 是一个面向 Windows 的批量解压工具：把一堆压缩包丢给它，它排队逐个处理——识别分卷、试密码、解压、校验，全部通过才把文件放到最终位置，然后按你的选择处理源压缩包。

它能处理分卷压缩包、加密压缩包、藏在 MP4/MKV 里的内嵌 ZIP，以及压缩包里套着的压缩包。

窗口名称：Smart 7z Ultra 适用平台：Windows 安装/便携版：自带 7-Zip 图形界面：PySide6 / Qt

开始前请确认

三件事值得在第一次解压前花一分钟弄清楚。

直接开始五分钟内跑通第一次解压。 弄清选项输出位置、暂存模式、清理策略，尤其后者。 出问题时按现象查表，多数情况有现成答案。
默认保留源文件：安装版、便携版和源码版的首次运行配置都使用 cleanup_policy=keep，不会自动清理源压缩包。需要清理时必须明确选择“回收站”或“永久删除”；第一次使用永久删除前应在常驻的 解压选项 行核对设置。
外部任务不会沿用窗口中的清理选项：普通命令行和未指定清理参数的第二个程序实例默认使用 keep。右键菜单会分别提供“智能解压到此文件夹”和“智能解压到此文件夹并删除”：前者保留源文件，后者使用 permanent，成功后永久删除源文件。图形界面中添加的任务仍会记住入队时所选的清理策略。
完整成功才交付：每个任务的输出都先解压到临时位置，程序核对文件数量、大小和结构无误后才移到最终目录。没完全成功但还有救的输出，会放进“非完全恢复”目录单独保留，不会和正常结果混在一起。

快速开始

  1. 选版本、装程序。安装版从开始菜单启动；便携版先完整解压到可写目录再双击 Smart7z.exe；源码版进入源码目录运行 python smart7z.py（需要自备 7-Zip 和 PySide6）。
  2. 定输出位置。勾选“解压到原目录”，输出就在每个压缩包旁边；取消勾选，全部输出进“目标目录”。
  3. 看一眼清理策略。默认“保留”。改为“回收站”或“永久删除”会在完整成功且清理检查通过后移走或删除源包；第一次使用先保留，核对结果后再决定。
  4. 加文件。几个文件就拖进窗口；整个目录用“扫描文件夹”，程序自己挑出压缩包。
  5. 点“开始”。程序先保存设置再跑队列；同一时刻只处理一个任务，小文件优先。

已经开着 Smart7z 时再启动一次，新进程只会把路径转给现有窗口，不会开第二套队列。

cd <Smart7z 源码目录>
python smart7z.py

# 发送路径并自动开始
python smart7z.py --start "D:/Downloads/example.7z"

# 发送路径但只入队，等待你在窗口里点“开始”
python smart7z.py --queue "D:/Downloads/example.7z"

安装与运行

三个版本怎么选

版本适合谁数据放哪
安装版固定在一台电脑上用。按当前用户安装，不需要管理员权限。%LOCALAPPDATA%/Smart7z，卸载后配置和恢复数据仍在。
便携版换机器、放 U 盘。ZIP 完整解压后运行，别改动目录结构。EXE 目录（靠 portable.flag 识别），配置、密码本、恢复状态全在便携目录里。
源码版审阅、测试、二次开发。源码根目录的 resources。发布包不含运行时恢复记录。

安装版和便携版自带 7z.exe；源码版要么装 7-Zip，要么把 7z.exe 放到源码根目录。

第一次启动

  • 源码版弹“找不到 7z.exe”：装 7-Zip，或放一份 7z.exe 到源码根目录，然后点击“重试启动”。已接收的任务仍保留在窗口中。
  • 窗口显示“正在启动”时，后台正在检查恢复状态并准备任务引擎，仍可添加或取消待处理任务。启动受阻时先在“选项”中修正路径等设置，再点击“重试启动”。
  • 点“开始”报配置保存失败：把目标目录、暂存目录、密码文件指到当前用户可写的位置。安装版查 %LOCALAPPDATA%/Smart7z；便携版确认 EXE 目录可写（只读目录无法保存设置）。
  • 随附的 code.txt 是空模板，需要自动试密码就按“一行一个”自己填。覆盖安装、升级不会动你已有的密码本，卸载也会保留。注意这是明文文件，别传到公共渠道。
  • 覆盖安装时，安装器先卸载当前用户已登记的旧安装版，再安装新版；配置、密码本与恢复数据保留。旧版卸载失败、取消或需要重启时停止安装；卸载登记损坏时需先修复或手动卸载。不通过删除整个安装目录来代替卸载。
  • 卸载完成后若新版安装失败，请重新运行安装器；此流程不承诺自动回滚旧程序。若选择新的安装目录，旧目录中保留的密码本不会自动搬迁，可在程序中指定其原路径。

界面一览

窗口从上到下：菜单栏 → 主操作栏 → 解压选项 → 路径与密码 → 队列按钮 → 任务表 → 任务详情/运行日志。

菜单栏

  • 右键菜单：注册或移除 Windows 资源管理器的右键入口（详见右键菜单）。
  • 文件扫描模式：三项永远只选一项，对勾标出当前模式。默认“仅兼容隐写者模式（非全读取）”，另两项是“深度扫描”和“普通模式”，详见扫描模式。
  • 选项 → 空间不足时等待：对勾开关，详见空间不足时等待。

解压选项、路径与密码

“解压到原目录”决定输出位置（见输出位置）；不勾时用“目标目录”。暂存模式、嵌套解压见对应章节。“密码文件”指向保存在磁盘上的明文密码本；“主密码”是当前会话优先尝试的密码，不写入配置，但成功使用后可能写入密码本（见密码压缩包）。

任务表

界面不再提供状态过滤按钮，所有任务始终留在表里，默认按大小升序。点列标题只改变显示顺序，不改变实际调度：已接纳的普通待执行任务按源包大小从小到大处理，同大小按接收顺序，人工输入后的恢复任务优先，当前任务不被抢占。状态列的排序约定：中断、部分恢复、失败、需密码、等待中、处理中、完成。拖动任务表和详情区之间的分隔条可以调整详情区高度。

工具栏不再提供手动暂停接收入口——它过去只延迟新增请求，不暂停当前解压，容易和“取消当前”混淆。扫描串行、IPC 排队和关闭时停止接收仍由程序自动处理。

取消扫描后重新扫描

目录扫描在后台跑，每次扫描有独立编号。点“取消所有”后当前编号作废，旧扫描迟到的结果不会混进新一批，可以放心立即重扫。

运行日志怎么读

日志只记需要你过目的事：失败、部分恢复、清理通知、外部请求。普通进度和成功完成看任务表就行，不刷屏。

一行日志的格式

[HH:MM:SS] {文件名}: 中文说明 / English message [MESSAGE_CODE] | {系统详情}
  • 方括号里的代码（如 JOB_FAILED）稳定不变，拿它搜本手册最方便。
  • | 后面是 Windows 或 7-Zip 的原始诊断，可能只有英文，程序原样保留。

红色标记

红色帮你从批量日志里快速挑出异常，判断仍以文字和代码为准。整条红 = 已经失败需要处理；短语红 = 有需要确认的结果但程序还能继续；其余保持原色。

显示方式消息代码
整条消息红色JOB_FAILED、ARCHIVE_BLOCKED、CONFIG_SYNC_FAILED、RECYCLE_FAILED、RECYCLE_FALLBACK_DELETE_FAILED
重点短语红色粗体RECOVERY_REVIEW、INTAKE_FULL、SCAN_FAILED、JOB_PARTIAL_RECOVERY、JOB_INTERRUPTED、JOB_PASSWORD_REQUIRED、USER_NOTICE、RECYCLE_FALLBACK_UNAVAILABLE、RECYCLE_FALLBACK_TOO_LARGE、RECYCLE_FALLBACK_DISABLED
保持原色其他代码（正常状态、操作确认和汇总）。

日志上限 500 行（满后每批移除最早的 100 行），单行最长 1600 字符。

解压选项总览

选项分几组，各自生效时机不同——有的立即生效，有的要等下次“开始”。先把这一节读完，能省掉很多“为什么没生效”的困惑。

设置保存与生效范围

程序不再提供单独的“保存配置”菜单项。正常关闭窗口时，程序会读取当前路径、菜单栏扫描模式与空间等待、下方解压选项、嵌套层数和清理策略，校验后以“先写临时文件、再替换原文件”的方式保存；点击“开始”时也会先执行同一套保存与应用流程，成功后才开始处理。

操作或任务状态实际行为
只修改窗口控件部分控件不会在每次点击后立即写盘，但通过当前窗口新添加文件或启动文件夹扫描时，“清理策略”和扫描模式等入队参数可能已经被记录。希望整批一致时，应先设置选项，再添加输入。
点击“开始”先自动保存并应用，再启动队列。保存或应用失败时，控件恢复到上一次已提交的配置，队列不会启动。
正常关闭窗口关闭流程开始前自动保存当前设置。保存失败时显示错误、恢复上一次已提交的配置并取消本次关闭，避免无提示丢失修改；再次关闭会保存恢复后的配置。
正在处理的任务任务启动时会取得执行配置快照，不会半程切换输出目录或暂存模式。清理策略更早在入队时就已固定；处理中修改任何设置，都不会改变该任务的源包处理方式。
未开始的任务点击“开始”保存设置后，队列中尚未开始的任务会采用新的普通执行设置，但清理策略仍使用入队时的值。切换清理策略只影响之后新增的任务，已有排队、待接纳、等待输入和历史任务均不改变。
命令行、右键菜单或第二个进程转交的路径只读取已经提交的配置，不读取当前窗口里尚未通过“开始”提交的控件值。正常关闭时保存的设置会在下次启动后生效。清理策略和“解压到此文件夹”仍以该次外部请求的明确参数为准；未指定清理策略时使用“保留”。
主密码不会落盘：这里指输入或保存配置时，不会把“主密码”写入 smart7z_config.json；配置保存的是密码文件路径。另有一项独立行为：密码成功用于完整解压后，程序会尝试把它写入明文密码本并置顶，因此不能理解为“密码永远不写磁盘”。

配置文件位置：安装版在 %LOCALAPPDATA%/Smart7z，便携版在 EXE 目录，源码版在源码根目录的 resources。需要手动维护字段时，查阅仓库中的 MAINTENANCE.md“配置与数据”。

输出位置

勾选“解压到原目录”：每个压缩包的输出放它旁边。取消勾选：所有输出进“目标目录”，此时目标目录必须填一个绝对路径，否则配置保存或运行会失败。

暂存模式

开启后，7-Zip 先解压到临时目录，程序检查路径安全、文件清单、数量、大小、返回码和输出上限；全部通过才把输出移到目标盘，再不覆盖现有文件地挪到最终位置。

解压到临时目录→ 检查路径和输出上限→ 核对文件、目录和大小→ 写入目标盘暂存目录→ 移到最终位置

同盘移动直接挪文件，不额外读一遍；跨盘复制时边复制边核对清单里已有的 CRC32。CRC32 对不上，输出进“非完全恢复”目录，源压缩包不动。

关闭暂存模式后，程序仍不会直接写最终路径，而是在目标目录下建 .smart7z_tmp_... 临时目录，校验通过后再移动。两者唯一区别是初始解压位置：开启用“暂存目录”，关闭用目标盘。

怎么选：想把初始解压放在指定临时盘上，就开启暂存模式；临时盘空间紧张、目标盘空间充足时，可关闭暂存模式，使用目标盘临时目录。暂存盘与目标盘不同会多一次跨盘复制，并需要两边都有足够空间。“直接模式”不是跳过校验，也不是把未完成文件直接写进正式目录。

空间不足时等待

菜单栏“选项”里勾选后，程序根据压缩包清单、输出上限和安全余量检查可用空间（暂存模式同时查目标盘和暂存盘）。空间不足时任务进入 SPACE_WAIT，默认最多等待 7200 秒（2 小时）。取消对钩只是跳过等待，解压中仍可能因空间不足而失败。

适合你准备稍后释放空间、又不想重新添加任务的情况。等待不会自动腾出空间；当前任务等待时，后面的解压任务也要等。暂时无法腾出空间就取消当前任务，调整好目录或空间后再添加。

嵌套解压

默认关闭。开启后，父任务完成（或产生部分恢复输出）时，程序扫描其输出目录，把发现的内层压缩包作为新任务入队。子任务沿用父任务的清理策略和嵌套限制，执行同样的安全预检。

适合明确想把“压缩包里套压缩包”继续拆开的情况，可以少做几次手工添加，但会增加任务数、耗时和空间需求。只想保留外层解压后的原样目录，或不确定里面是否有程序资源包时，保持关闭。

为避免把游戏和程序的资源包误当成压缩包，扫描会识别结构有效但没有自解压载荷的普通 Windows EXE，保护其所在目录和父目录不再继续解压；保护不会越过本次输出根目录。改名成 .exe 的普通压缩包、以及尾部带完整 ZIP/7z 载荷的自解压文件不受此保护，照常处理。

限制：max_nested_depth=2（最大深度）、max_nested_children=50（每根批次最多子任务数）、max_nested_output_bytes=0（0 为不单独限制总字节，普通输出上限和磁盘检查仍有效）。循环检测用真实路径、设备号、文件标识、大小和修改时间。

永久删除回退

“选项”对话框“清理”组中的“回收站不可用时允许永久删除源文件”默认关闭。关闭时，选择“回收站”清理策略后，如果某卷明确不支持回收或文件超过该卷回收站容量上限，源文件保留在原处，任务照常完成并显示 RECYCLE_FALLBACK_DISABLED 通知。勾选后，这两类文件在有恢复日志保护的前提下被永久删除，无法从回收站恢复。该开关只影响“回收站”策略；“永久删除”策略不受此开关保护，清理检查通过后仍会永久删除。

只有源文件已有备份或能够重新获取，并且你明确接受“回收失败条件下不保留”时才考虑开启。设置未知、权限错误或文件被占用，不会因此变成永久删除许可。恢复日志用来处理删除过程中的中断，不是已删除文件的备份。

密码压缩包

密码只在处理过程中临时使用，不会写入长期任务记录；日志里也不记密码值。但密码文件本身是明文——请勿把密码文件发到公共渠道，也别指望它替代密码管理器。

程序按什么顺序试密码

本次手动输入→ 会话主密码 / 最近成功密码→ 无密码探测→ 密码文件逐行候选→ 弹出密码输入

用法

  • 密码文件纯文本、一行一个，默认文件名 code.txt。相对路径通常按配置所在的可写状态目录解析：安装版为本地用户目录，便携版为 EXE 目录，源码版为 resources；升级时可能继续使用旧程序目录中的非空密码本。自定义绝对路径按指定位置使用。
  • 一批加密包共用一个密码时，先填“主密码”再开始。
  • 一个密码用于完整成功的任务后，会成为本批次后续加密包的优先候选；程序同时尝试把它写到密码文件顶部。即使它最初来自“主密码”或手动输入，也可能写入这个明文文件。
  • 同一批次内立即生效，无需重启或重新添加任务。后续任务重新读取密码文件；外部编辑会在下一次自动尝试时生效。当前已开始的一轮尝试不会中途更换候选。
  • 例如同批有十个包，首个包成功后，后面的包可以优先试同一密码，减少重复输入和无效尝试。手动调整密码本顺序只改变密码本这一组候选，会话主密码仍排在前面；密码本写入失败时，本次会话仍可优先使用成功密码，但不能认为磁盘上的顺序已保存。
  • 文件头可见的加密包会复用无密码状态下已取得的完整清单；等待手动密码期间源文件没变的话，重新入队也不会再读一遍清单。
  • 自动候选全部失败进入密码提示后，每次手动提交只试本次输入；输入错误会立即再提示。
  • 已确认加密的包在解压阶段不会再做必然失败的无密码尝试；列清单时某密码已解锁文件头的，解压直接先用它。
  • 手动提交或跳过后，输入框立即清空、提示区收起。点“跳过”任务标记为 SKIPPED，源文件不清理。

密码文件限制：超过 4 MiB 整份忽略且不回写；最多用前 10,000 个候选；单行超 4,096 字符的候选忽略。这些候选限制不会截断原密码本。首尾空格属于密码内容，不会自动去除。读取失败、无法保留原编码或回写前检测到外部修改时，原文件保持不变，成功密码仍可在本次会话中优先使用。

伪装文件与内嵌 ZIP

有些视频文件里藏着 ZIP。Smart7z 可通过容器结构定位支持布局的 MP4/MKV 隐写 ZIP，并检查 ZIP64 记录、诱饵签名、随机区和空 mdat 尾缀。遇到未知或无法确认的布局仍可能需要深度扫描或人工复核，不保证每个伪装文件都能恢复。

能识别的三类布局

普通 MP4 追加 ZIP

ZIP 直接结束于文件尾，或带受支持的隐写者诱饵签名、随机区和空 mdat 尾缀。

ZArchiver free 原子

验证 ftyp 后的 free 原子，要求完整 ZIP 与原子载荷边界精确一致。

MKV ZIP 附件

通过 EBML 和 SeekHead 定位 Attachments/FileData，跳过大型 Cluster，校验附件内完整 ZIP。

操作步骤

  1. 保持菜单栏“仅兼容隐写者模式（非全读取）”开启，扫描文件夹。
  2. 未知布局没被发现时，改用“深度扫描模式（全文件读取）”，或“添加文件”直接选单个文件。
  3. 点“开始”。只有签名、越界或无结构证据的候选不再弹出提示；相同格式与字节范围的重复候选合并。唯一且边界与结构完整验证的 ZIP/ZIP64 自动继续解压。
  4. 唯一、有结构证据、边界不是暂定但仍未达到自动放行条件的候选，会标为“推荐”并默认选中，确认后继续。多个有结构证据的候选或边界不确定时不预选，须人工选择；HIGH 是规则分档，不等于已通过精确验证。
  5. 需要密码时，提示区优先显示密码输入；任务表也把需密码任务放在候选复核任务之前。同类任务仍按选定列排序。忽略噪声候选不等于跳过整个文件，也不会授权删除源文件。
  6. 只选来源可信、边界完整的高置信候选。解压校验通过后，输出和普通任务一样保存。
多候选需要人工选择：可免确认自动继续的唯一 ZIP/ZIP64 候选，必须通过中央目录、本地文件头、条目数量和精确边界检查；“文件已入队”本身不代表通过这些检查。发现多个候选、边界不确定或只能部分恢复时，程序不会清理原文件。

这套处理规则在维护记录中称为 B'：减少只凭几个相似字节造成的无效提示，遇到真正不确定的结构仍让你决定。看到“推荐”可先核对范围和说明，不必把它当成程序已替你确认；没有把握就跳过并保留原文件。源文件清理针对整个外层文件，想保留原视频或图片时必须选择“保留”。

嵌套解压的边界

嵌套解压（见选项说明）开启后，程序会继续处理解压结果中的内层压缩包。两个值得知道的边界行为：

  • 部分恢复也会继续扫：只要父任务留下了可恢复输出且嵌套开启，程序就会扫描该目录。不完整的父任务也可能生成子任务——检查这些任务的输出。
  • EXE 目录保护：结构有效、无可确认自解压载荷的普通 Windows EXE 会保护其本目录和父目录不被继续解压，避免游戏或程序的资源包被拆开。改名成 .exe 的压缩包和边界完整的自解压文件不受保护。

源文件清理

清理是唯一会删你源文件的功能，规则也最严格：只有任务 COMPLETE、输出复查通过、源文件没变、分卷信息可靠、内嵌候选无歧义时才执行。

三种策略

策略行为何时用
keep / 保留
默认		保留源压缩包。首次使用、需要核对结果、重要资料或来源不明的文件。
recycle / 回收站逐卷检查回收站设置。可以回收的只进回收站；卷明确不支持回收或文件超容量上限时，默认保留源文件并提示（RECYCLE_FALLBACK_DISABLED）。只有在“选项”中勾选“回收站不可用时允许永久删除源文件”后，这两类才改走有恢复日志保护的永久删除。希望通常可以恢复，且不接受回收站不可用时被永久删除。
permanent / 永久删除不可恢复成功后再次核对源文件身份（设备号、文件标识、大小、修改时间），先记恢复日志，再移入同盘隐藏暂存目录并永久删除。空间紧张，且文件已有备份或可以重新获取。

普通命令行和第二个实例默认 keep；指定 --delete-source 或选右键“并删除”才用 permanent。任务的清理策略在入队时固定；中途改选项只影响之后新增的任务，不改变已有排队、等待输入或执行中的任务，也不覆盖外部请求明确指定的策略。

“回收站”策略怎么决定删除方式

清理一组分卷前，程序先确认所有源文件仍在原处，再按卷 GUID 读取当前用户的回收站设置（NukeOnDelete 和 MaxCapacity）并核对每个文件大小。任何一项读不清或源文件缺失，整组清理停止。

检查结果程序怎么做能否恢复
固定磁盘允许回收，文件没超容量上限通过 Windows IFileOperation 严格回收，禁止 Shell 暗中改成永久删除。可从回收站恢复。
非固定磁盘、启用 NukeOnDelete、或 MaxCapacity 为 0默认保留并提示；仅开启永久删除回退后，才先写恢复日志，再移入同盘隐藏暂存目录并永久删除。默认仍在原处；开启回退并删除后不能恢复。
单文件超过该卷 MaxCapacity默认保留并提示；仅开启回退后走恢复日志、同盘暂存和永久删除，不让 Windows 自行暗删。默认仍在原处；开启回退并删除后不能恢复。
源文件预检后变化、设置未知、锁定、权限或 COM/Shell 错误停止清理，不把这类错误解释为永久删除许可。未处理的源文件保留。

分卷任务何时只处理一部分：整组预检失败时一个卷都不动；只有清理已经开始后某卷运行时出错才会部分处理。已进回收站的卷可手工恢复；未开启回退开关时，不满足回收条件的卷一律保留原处。

五条通知同时出现在“任务详情”和“运行日志”。{count} 按消息分别表示已永久删除或已保留的源文件数，不是解压出的文件数；方括号代码不变，便于检索。

代码界面显示含义

清理会被阻止的情况

  • 状态不是 COMPLETE（FAILED、PARTIAL_RECOVERY、INTERRUPTED、SKIPPED）。
  • 7-Zip 读清单或解压返回警告，且没有唯一、边界精确的高置信候选确认结果。
  • 分卷缺失、分卷元数据与发现结果不一致、卷索引不可信。
  • 源文件缺失、是链接或重解析点，或运行期间设备号、文件标识、大小、修改时间变化。
  • 跨盘移动输出时 CRC32 与清单不一致，或文件、目录、数量、大小不一致。
  • 输出写入磁盘、移动到最终位置、更新恢复日志或暂存源文件失败。
  • 内嵌 ZIP 候选有歧义、边界不确定或置信度较低。
  • 输出移到最终位置后的复查失败。

界面中选“永久删除”会弹确认框。这些检查能处理意外中断、写入长度不足、进程终止和输出不完整，但防不了操作系统仍报告成功的磁盘静默损坏。

恢复与临时文件

Smart7z 用恢复日志跟踪自己创建的每个临时目录。程序意外退出后，下次启动能据此恢复或保留现场。你通常不需要碰这些文件——知道它们是什么就够了。

对象典型名称是什么
会话临时目录Smart7z_Session_...暂存模式下保存解压输出和中间文件。正常退出或下次启动时自动清理（仅限能确认归程序所有的）。
所有权标记.smart7z-owner.json标明会话目录由 Smart7z 创建。别手工复制它。
输出暂存目录.smart7z_commit_...输出移到最终位置前的暂存区。异常中断后恢复日志会保留其中可恢复的内容。
源文件暂存目录.smart7z_cleanup_...永久删除前暂存已复查的源文件。中断后优先恢复原路径；原路径已有文件时转移到可见的冲突目录。
部分恢复目录非完全恢复保存警告、CRC32 不一致或复查未完全成功时仍可恢复的文件。人工检查后再动。
恢复日志与锁文件recovery-v1.json / recovery-v1.json.lock意外退出后继续恢复，防止多进程同时改记录。文件损坏时先备份再让程序重新生成。
断电或进程意外退出后：已登记但未移到最终位置的输出会保留，不会被当垃圾清掉。永久删除停在“已暂存未删除”时，下次启动按设备号、文件标识、大小和修改时间复查并恢复原路径；原路径被占用则移到可见冲突目录，不覆盖现有文件。

目录内容变化时不会自动删除：恢复日志按相对路径、类型、大小、修改时间和条目数生成元数据摘要（不读内容算哈希）。目录中出现新增、替换或未登记内容时，整个目录保留。

命令行、单实例与右键菜单

命令行

# 默认：路径会自动开始
python smart7z.py "D:/Downloads/a.7z"

# 只加入队列，不启动处理
python smart7z.py --queue "D:/Downloads/a.7z"

# 明确自动开始
python smart7z.py --start "D:/Downloads/a.7z"

# 解压到源文件所在目录，并保留源文件
python smart7z.py --start --extract-here --keep-source "D:/Downloads/a.7z"

# 解压到源文件所在目录；完整成功后永久删除源文件
python smart7z.py --start --extract-here --delete-source "D:/Downloads/a.7z"

# 停止解析选项，后面的值都当路径
python smart7z.py -- --queue

--queue 和 --start 控制何时开始；--keep-source 和 --delete-source 控制清理。没指定清理参数时用 keep。--extract-here 忽略窗口里配的目标目录，输出放各源文件旁。

单实例

当前用户登录会话内，安装版、便携版和源码版共用一个窗口及队列。再启动时，新进程通过本机 IPC 把路径和参数转给现有窗口后退出；不带路径时激活现有窗口。本版本没有“允许多窗口”设置。

各副本通过 %LOCALAPPDATA%/Smart7z/ipc-v3.json 查找已有窗口。这里只有连接信息，各副本的配置、密码本和恢复日志不会合并；任务由已经打开的窗口处理，清理策略等明确参数仍以该次请求为准。升级前先关闭旧版本窗口，避免旧便携版仍使用自身目录中的连接信息。

转发结果四种：accepted（已接收，新进程退出）、rejected（队列满或正在关闭；确定失败以非零码退出）、indeterminate（到达但无确认，先查现有窗口队列再决定重试）、unavailable（找不到现有实例，最多等 15 秒再接管，不会开第二个调度器）。

右键菜单

菜单栏“右键菜单 → 添加右键菜单”为当前用户注册两个资源管理器菜单项（写 HKCU 注册表，无需管理员权限）：

菜单项输出位置源文件处理
智能解压到此文件夹源文件所在目录keep，保留源文件。
智能解压到此文件夹并删除源文件所在目录permanent；完整成功并通过全部复查后才永久删除。

两项都自动开始处理。右键目录时先扫描再逐项入队。

安装版升级先备份当前 Smart7z 菜单，卸载旧安装版后恢复被删除的入口，再把属于旧安装目录的主程序或 Smart7zShell.exe 命令更新到新安装目录。其他副本接管的入口保留；备份位于 %LOCALAPPDATA%/Smart7z/upgrade-menus-*。本版卸载只移除本安装目录拥有的菜单。手动执行“移除右键菜单”则是主动移除当前 Smart7z 菜单。

右键窗口何时自动关闭

只有“最初由右键菜单创建”的独立窗口才有资格自动关闭：所有任务无异常完成、无提示、扫描和待接纳全部结束、无密码或候选确认挂起时，按正常流程保存配置并退出。以下任一情况窗口保留：窗口原本是普通方式打开的；右键窗口后来又被双击激活；出现失败、部分恢复、中断、跳过、需密码、候选复核、扫描失败、未接纳请求或程序异常；没发现任何任务。框选多个压缩包时，后续右键请求会重置关闭检查的等待，避免第一个小包先完成就关窗漏掉后面的。

“并删除”不走回收站：源压缩包通过全部清理检查后会被永久删除。要保留恢复余地，选不带“并删除”的菜单项。

升级到双菜单版本后：先关旧实例，再运行新版重新执行“添加右键菜单”，程序会移除旧的单菜单项。

取消与关闭

取消任务不等于删除源文件，也不能撤销已经完成的清理。只想停止某几个任务时用“取消选中”；只想停止正在解压的任务时用“取消当前”。本手册中的“取消所有”指工具栏的“取消所有待处理”：仍让当前任务继续，该任务完成后可能按它的清理策略处理源文件。

操作效果源文件输出
取消选中移除选中的未完成任务，包括等待密码或候选选择的任务；活动任务先请求安全停止。未选中的任务和已结束的历史行保留。取消本身不删除源文件。迟到的后台事件不会让已移除任务重新出现；已完成的输出不撤回。
取消当前通知当前任务停止，结束正在运行的 7-Zip 进程。保留。未移到最终位置的临时输出会清理；已完成的输出不撤回。
取消所有当前任务继续；其余未完成任务直接从任务表和调度器移除（不生成“已中断”历史行），同时停止目录扫描、清空待接纳请求。被移除任务保留源文件；当前任务仍按其策略处理。旧扫描迟到的结果被丢弃，可立即重新扫描。
关闭窗口只要还有未完成任务或扫描，即使只是排队或等待也需要关闭确认，默认选择“否”；等待密码、候选确认、空间以及启动期间已接收的输入都包括在内。确认退出后停止接收新请求，请求调度器、扫描和初始化线程退出。关闭不会撤销已完成的清理；未完成任务按安全中断流程保留源文件。下次运行时，未完成任务需要重新添加。取消关闭不会停止任务或扫描；只有已结束记录时不额外确认。后台尚未停止时保留实例锁，所有扫描线程共用约 1 秒等待时间，调度器可能需要更久。
右键任务自动关闭仅限右键菜单独立创建且未被再次激活的窗口；全部任务无异常完成后按正常流程退出。按每个任务入队时的右键策略处理。任一异常、提示或恢复复核都会保留窗口。

任务状态

状态含义你要做什么
QUEUED已入队，等待启动或前面的任务。手动添加的需点“开始”；自动开始的等就行。
DISCOVERING正在识别结构和分卷。等待。
GROUPED已识别为一组分卷。若随后报缺卷，补齐整组。
STANDALONE按单个压缩文件处理。等待。
STEGO_CANDIDATE_REVIEW需要选择内部结构候选。选可信候选或跳过。
LISTING正在读压缩包清单。等待。
PASSWORD_ATTEMPT正在试密码候选。等待。
PASSWORD_REQUIRED所有候选失败，需要手工密码。输入密码或跳过。
PLANNED清单检查通过，已确定输出空间。等待。
SPACE_WAIT磁盘空间不足，等待中。释放空间或取消。
EXTRACTING正在解压。等待；可取消当前。
VERIFYING正在核对解压结果。等待。
COMMITTING正在把输出移到最终位置。别手工移动目标目录。
COMPLETE输出已完整写入并通过复查。检查输出；源文件按入队策略处理。
PARTIAL_RECOVERY未完整成功，保留了可恢复输出。人工检查“非完全恢复”目录。
FAILED失败且无可提交输出。看错误分类和日志。
SKIPPED用户跳过。需要时重新添加。
INTERRUPTED取消、关闭或调度停止。需要时重新运行。

错误分类

错误含义常见处理
NOT_ARCHIVE7-Zip 无法作为压缩包打开。确认文件完整；怀疑有内嵌 ZIP 就直接添加做结构扫描。
UNSUPPORTED_FORMAT格式不支持。升级 7-Zip 或换工具。
BAD_PASSWORD密码错误或缺失。输入正确密码，维护密码文件。
MISSING_VOLUME分卷缺失。补齐所有卷。
CORRUPT_HEADER头部损坏。重新下载或用恢复工具。
TRUNCATED_INPUT输入截断。重新获取源文件。
DISK_FULL空间不足，或预计输出超配置上限。释放空间、换目标目录或调整上限。
TIMEOUT7-Zip 操作超时。重试或检查文件/磁盘。
CANCELLED用户取消或关闭。需要时重新开始。
UNSAFE_PATH清单或输出含不安全路径。别强行解压到工作目录；隔离分析。
OUTPUT_CONFLICT移到最终位置时冲突或失败。检查目标目录和“非完全恢复”目录。
VERIFY_FAILED输出与清单不一致。检查“非完全恢复”目录。
INTERNAL_ERROR程序内部或系统调用异常。保留日志和源文件，重新运行或反馈开发者。

术语速查

术语含义
显式输入用户直接指定的文件（“添加文件”、拖拽、命令行文件路径）。
自动发现扫描目录或嵌套输出时，由程序判断哪些文件入队。
外层文件可能包含内嵌压缩包的文件，如 JPEG、MP4、MKV。
候选程序在外层文件中找到的一段可能属于压缩包的数据。
完整校验7-Zip 读清单和解压都无警告；文件、目录、数量和已知大小一致，无输出上限或路径安全问题。
清理源文件确认输出完整成功后，按任务策略保留、回收或永久删除源压缩包。
