Smart 7z Ultra 1.0.0 Windows x64 发行版
======================================

目录
----
- 安装版：安装版\Smart7z-1.0.0-setup-windows-x64.exe
- 便携版：便携版\Smart7z-1.0.0-portable-windows-x64.zip

使用提示
--------
- 安装版按当前用户安装，不需要管理员权限。
- 便携版必须先完整解压到可写目录，再运行 Smart7z.exe。
- 两个版本都自带 7-Zip，无需另外安装。
- 首次运行默认保留源压缩包，随附密码本为空。
- 便携包包含 QtBase、PySide6 和 Shiboken6 的版本对应许可证正文；对应源代码随源码包发布，版本与 SHA256 见 licenses/Qt-PySide6-source-manifest.json。
- Windows 运行库采用 PySide6_Essentials 6.11.1 的单一 x64 VC 运行库副本；文件版本、哈希和官方许可文档随包放在 Microsoft-Visual-Cpp-Runtime-NOTICE.txt 与 licenses/ 下。
- 当前程序未进行代码签名，Windows 首次运行时可能显示信誉提示。
- 完整使用说明已包含在程序或便携包内的 Smart7z-User-Manual.html。

本次修正
--------
- 菜单栏新增“文件扫描模式”三级互斥对钩菜单：深度扫描模式（全文件读取）、仅兼容隐写者模式（非全读取）、普通模式；默认选择隐写者兼容模式。新增“选项 → 空间不足时等待”，并删除下方工具栏重复按钮。
- 兼容 cenglin123/SteganographierGUI 的三类布局：普通 MP4/WinRAR 追加 ZIP、mp4(zarchiver) 的 free 原子 ZIP、MKV 附件 ZIP。
- 兼容模式只读取 BMFF/EBML 容器头、Matroska SeekHead/附件元数据、ZIP 尾部、中央目录和被引用的本地文件头；大尺寸视频主体和 Cluster 直接按长度跳过，不做顺序全读。
- 普通 MP4 还会精确校验隐写者当前版本的两组诱饵压缩签名、5-10 KiB 随机区和空 mdat 尾缀；旧式 MP4 直接追加完整 ZIP 到文件尾也兼容。
- 修复部分 SteganographierGUI 文件使用 ZIP64 记录但经典 EOCD 字段未饱和时漏掉真实 ZIP、只暴露尾部 RAR5 诱饵的问题；现在严格核对 ZIP64 记录长度、定位器、磁盘号、条目数、中央目录和相对偏移。
- 深度扫描、直接添加和拖入都会优先识别隐写者结构与随机诱饵尾缀；命中时只复用真实 ZIP 候选，未命中才进入通用 ZIP、7z 和 RAR 扫描。
- 修复“仅兼容隐写者模式（非全读取）”的文件夹扫描已找到精确候选后，执行器仍直接打开原视频并报 NOT_ARCHIVE 的问题；预计算候选现在会授权结构切割，三个超过 3 GB 的真实 ZIP64 候选均可由 7-Zip 正常打开。
- 深度扫描的通用回退保持一次流式读取并把预检结果交给后续任务复用，避免同一个大文件重复扫描。
- 文件夹扫描期间临时显示当前文件进度，完成、取消或新一代扫描接管后自动隐藏。
- 任务详情区可拖动调整高度；任务表“源文件”列更名为“源包处理”。
- 普通待处理任务默认按源包大小从小到大执行，同大小保持入队顺序；密码和候选人工处理完成后的任务优先恢复。
- 手动密码提交或跳过后清空输入、收起提示区并恢复任务区域布局。
- 自动候选全部失败后，每次手动提交只尝试本次输入；错误手动密码不会重新遍历本批次成功密码或 code.txt。
- 修复隐写候选处理后可能在 C:\Temp_Smart7z 留下空 stego 会话目录的问题；只回收所有权可验证且仅含空固定脚手架的会话，未登记内容、链接和重解析点仍会保留。
- 覆盖安装时，若旧安装地址存在非空密码本而新状态目录只有空占位或没有密码本，程序继续使用旧地址。
- 嵌套解压会先识别普通 Windows PE，并保护 EXE 所在目录及其父目录；保护边界不越过当前压缩包输出根。普通压缩包改名为 .exe，或有效 PE 尾部存在唯一、完整且边界明确的 ZIP/7z SFX 时，仍按嵌套压缩包处理。
- 修复主窗口正在关闭时，多选右键辅助进程收到 server_stopping 后直接失败的问题：新进程现在会在有界时间内重试转交，并且只有取得命名互斥量后才初始化调度器和恢复日志。
- 文件头可见的加密 ZIP 复用无密码状态下已经取得的完整清单；等待手动密码后源文件未变化时也不重复列清单。文件头加密或源文件变化时仍重新读取。
- 密码顺序调整为“本次手动输入、本批次成功密码、无密码探测、密码文件其余候选”；已确认加密后的解压不再做必然失败的无密码尝试，成功密码仍提升到 code.txt 首行。
- 7-Zip -slt 清单改为有界流式解析。正常完成主要降低峰值内存；条目数超过 max_manifest_entries、max_output_files 或内部解析安全上限 200000 时，在第“有效上限 + 1”条终止列表进程并按原有安全规则拦截；配置更高不会绕过内部上限。
- 增加列表、解析、预检、解压、输出扫描和任务总耗时诊断；指标仅在内存和任务详情中使用，不写入恢复任务数据，也不记录密码。
- 自动识别失败后的 -tzip/-trar/-t7z 回退优先使用文件开头的可靠签名，签名不可用才参考扩展名；密码错误、缺卷、取消、超时和内部解析错误不做无意义重列。
- 优化“扫描文件夹”的文件读取：常见压缩格式先用 64 KiB 文件头/文件尾完成轻量识别，证据明确时不再扩展到完整边缘读取。
- 深度模式下的媒体内嵌 ZIP 检查由多轮全文件特征扫描收敛为一轮 ZIP 结构流式扫描，同时继续逐项校验中央目录、本地文件头、条目数量和精确边界。
- 默认兼容模式进一步避免顺序读取 SteganographierGUI MP4/MKV 的媒体主体；MKV 优先使用 SeekHead 直达附件，没有 SeekHead 时按已知元素长度跳过 Cluster。
- 只有由资源管理器右键菜单独立创建的窗口，才会在全部任务无异常完成后自动关闭。
- 普通窗口接收右键任务不会自动关闭；右键窗口随后被双击激活时，也会取消自动关闭并保留窗口。
- 失败、部分恢复、中断、跳过、需密码、候选复核、扫描失败、请求未接纳、任务通知和恢复复核都会保留窗口，方便查看专属错误。
- IPC 分发、界面回调或自动关闭阶段如遇未预期程序异常，也会取消自动关闭并保留窗口。
- 多选右键请求使用短暂静默期和请求代次检查，避免第一个小压缩包完成后漏接后续文件。
- 修复资源管理器框选多个压缩文件后使用右键菜单时，多个辅助进程可能同时初始化恢复日志并提示锁不可用的问题。
- 启动阶段现在只允许一个主实例创建窗口、调度器和恢复日志；其余右键请求会等待并转交到同一窗口。
- 安装器升级时不再覆盖已有的 code.txt，卸载时也保留该密码本。

验证
----
- 最终源码通过 372 项自动化测试，其中真实 7-Zip 集成用例全部通过。
- 20,000 条目 ZIP 的 5 次中位数基准：完整捕获后解析为 10,211.71 ms / 49.70 MiB，流式完整解析为 10,062.58 ms / 9.02 MiB；上限 100 时在第 101 条停止为 342.33 ms / 0.13 MiB。流式解析对正常完成只带来约 1.5% 时间变化，主要收益是内存和超限提前终止。
- 新便携版已验证：单个正常右键自动退出、多进程右键全部接纳后退出、普通窗口接收右键后留窗、右键窗口被双击激活后留窗、损坏压缩包报错后留窗。
- 安装器支持直接覆盖安装；覆盖前应关闭正在运行的 Smart7z。程序文件会更新，已有 code.txt、用户配置和恢复数据会保留。

校验
----
在本目录运行：
  Get-FileHash -Algorithm SHA256 .\便携版\Smart7z-1.0.0-portable-windows-x64.zip
  Get-FileHash -Algorithm SHA256 .\安装版\Smart7z-1.0.0-setup-windows-x64.exe

结果应与 SHA256SUMS.txt 一致。
